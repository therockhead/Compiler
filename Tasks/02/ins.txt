HOW TO APPROACH EACH TASK
1. Read the whole task file first. Output format and error rules are
compared exactly.
2. Before coding, draw a transition diagram for every token class
(Dragon Book 3.4) and decide how many characters of lookahead you
need.
3. Build in this order:
a) buffered reader (advance/peek), then position tracking (line:col)
b) valid tokens, then maximal munch
c) error detection, then error recovery
4. Run the 5 given tests and compare your output against the expected
output. Then write your own edge cases: empty file, no trailing
newline, only errors, file ending inside a string or comment.
5. Do the tasks in order. Ideas carry over, tokens do not.
